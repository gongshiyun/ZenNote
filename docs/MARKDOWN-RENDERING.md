# ZenNote Markdown 实时渲染细节规范

> 本文档定义 ZenNote 编辑器中每一种 Markdown 语法的渲染行为、光标交互、边界情况和实现要点。
> 目标：做到 Typora 级别的 WYSIWYG 体验，每个细节都有据可依。

***

## 1. 核心渲染哲学

### 1.1 asdasd两种视图状态

编辑器中的每个 Markdown 节点始终处于两种状态之一：

| 状态  | 触发条件     | 视觉效果                           |
| --- | -------- | ------------------------------ |
| 渲染态 | 光标不在该节点内 | 显示富文本渲染结果，所有语法标记不可见            |
| 编辑态 | 光标进入该节点  | 语法标记以浅色浮现（40-50% 透明度），正文保持完整样式 |

切换时机：：：光标移动时即时判断：：，不延迟。用 ProseMirror 的 `Selection` 变化事件驱动。

### 1.2 语法标记颜色

统一使用文档级 CSS 变量：

| 模式 | 色值        | 说明                                     |
| -- | --------- | -------------------------------------- |
| 亮色 | `#C4C4C4` | 比上次定的 `#C0C0C0` 略亮，避免和正文 `#888` 次级文字混淆 |
| 暗色 | `#6A6A6A` | 在 `#D4D4D4` 正文背景下刚好可见但不抢眼              |

标记字号可以与正文字号相同，不需要缩小。Typora 的做法是标记颜色变淡但不改变大小，这样输入时视觉不跳。

### 1.3 渲染态与编辑态的切换

* 光标通过鼠标点击或键盘方向键移动

* ProseMirror 的 `Selection` 是节点级别的（node selection）或文本级别的（text selection）

* 当 `$from.pos` 和 `$to.pos` 跨越一个 mark 的边界时，该 mark 进入编辑态

* 具体：对于行内格式（bold/italic/code/link），当光标在 mark 的 `from` 和 `to` 之间时，显示语法标记

## 2. 行内格式

### 2.1 加粗 `**text**` / `__text__`

渲染态

：文字以 700 字重显示，`**` 不可见。

编辑态

：两侧 `**` 以语法标记色显示。文字保持 700 字重（不应因为光标进入就取消粗体）。

快捷键

：

* `Ctrl+B`：选中文字时包裹 `**`；光标在粗体文字内时移除 `**`（toggle）

* 无选中时按 `Ctrl+B`：插入 `****` 并将光标置于中间

边界情况

：

| 场景           | 行为                                             |
| ------------ | ---------------------------------------------- |
| 输入 `**`      | 立即在后插入配对的 `**`，光标置于中间                          |
| 只输入了一个 `*`   | 显示为字面 `*`（不匹配成对）                               |
| `***text***` | 粗体+斜体，见 2.2                                    |
| 跨行粗体         | 不支持  。Markdown 标准不允许粗体跨段落                      |
| `**` 前后有空格   | `** text**` → 字面星号，不渲染粗体。只有 `**text**` 紧凑格式才生效 |
| 中文与 `**` 之间  | `**中文**` 正常生效。中文前后不需要空格                        |

实现要点

：Milkdown 的 marks 系统已内置 bold。只需自定义 mark view 的 CSS：渲染态隐藏 delimiter，编辑态显示。

***

### 2.2 斜体 `*text*` / `_text_`

渲染态

：文字以斜体（`font-style: italic`）显示，`*` 不可见。

编辑态

：两侧 `*` 以语法标记色显示，文字保持斜体。

快捷键

：

* `Ctrl+I`：toggle 斜体，逻辑同 2.1 的 `Ctrl+B`

边界情况

：

| 场景                  | 行为                                                  |
| ------------------- | --------------------------------------------------- |
| `_` 在单词中间           | `some_text` →   不  渲染为斜体。下划线仅当两侧有空格或标点时才作为斜体标记      |
| `*` 用于列表            | 行首 `* ` 是列表标记，不是斜体。这个由 Markdown parser 区分，编辑器无需额外处理 |
| `*text*` 后紧跟中文      | `*text*中文` → 正常渲染，`*` 后的中文不影响闭合检测                   |
| 单个 `*`              | 显示为字面星号                                             |
| `***bold-italic***` | 同时渲染为粗体+斜体。`***` 视为粗斜体标记。当光标进入时，显示三个星号              |

实现要点

：Milkdown 的 emphasis mark 需要配置 `_` 在词中间的规则，与 CommonMark 规范一致。

***

### 2.3 粗斜体 `***text***` / `___text___`

渲染态

：文字同时以 700 字重 + 斜体显示。

编辑态

：两侧各显示三个 `***` 标记。

注意

：`***` 和 `*__` 等混合形式也是合法的：

* `**bold** *italic*` → 分开处理，各自独立

* `**_bold-italic_**` → 等同于 `***bold-italic***`

***

### 2.4 删除线 `~~text~~`

渲染态

：文字带删除线（`text-decoration: line-through`），颜色略淡于正文（可选）。

编辑态

：两侧 `~~` 以语法标记色显示。

快捷键

：`Ctrl+Shift+X`（非标准，但很多编辑器用这个）

边界情况

：

| 场景         | 行为                                                |
| ---------- | ------------------------------------------------- |
| 单个 `~`     | 显示为字面波浪号                                          |
| `~~` 中间无内容 | `~~~~` → 不渲染删除线，四个波浪号视为字面字符                       |
| 嵌套删除线与粗体   | `~~**text**~~` → 粗体 + 删除线。外层的 `~~` 和内层的 `**` 各自独立 |

***

### 2.5 行内代码 `` `code` ``

渲染态

：文字以等宽字体、**浅色背景**（亮色 `#F0F0F0`，暗色 `#2D2D2D`）、6px 圆角、2px 内边距显示。反引号不可见。

编辑态

<br />

：两侧反引号以语法标记色显示，等宽背景保持不变。

快捷键：`Ctrl+`` ` 已被源码切换占用。行内代码用 `Ctrl+Shift+C` 或直接输入反引号触发。

边界情况

：

| 场景       | 行为                                  |
| -------- | ----------------------------------- |
| 代码内含反引号  | ` ` `code` ` ` → 用双反引号包裹。编辑器应识别这种形式 |
| 代码内含双反引号 | ` ``` `code``` ` ` → 用三反引号包裹        |
| 反引号后紧跟字母 | `` `code`text `` → 正常闭合，后续文字不受影响    |
| 多行行内代码   | 不支持  。反引号内包含换行符时，渲染为普通文字。行内代码就是单行的  |

实现要点

：Milkdown 的 `inlineCode` mark。自定义 view 时需要注意多反引号的正确解析。

### 2.6 链接 `[text](url)` 和 `[text](url "title")`

渲染态

：

* 显示为蓝色带下划线的可点击文字

* 鼠标悬停时显示 URL tooltip（`title` 属性作为 tooltip 内容）

* 点击：在系统默认浏览器中打开 URL（通过 Tauri 的 `shell.open`）

编辑态

：

* 光标在 `[text]` 内时：`[` 和 `](url)` 以语法标记色显示，文字保持蓝色

* 光标在 `(url)` 内时：整个 `[text](url)` 语法可见，光标所在部分可编辑

* 实际上 Typora 的做法是：光标进入链接区域时，显示一个浮动的小窗，包含 URL 输入框 + 文字输入框。但这对 Milkdown 来说实现复杂度较高，首期可简化为光标进入时语法标记全显

快捷键

：

* `Ctrl+K`：选中文字时包裹 `[文字](url)`，光标跳到括号内

* 无选中时：插入 `[](url)`，光标在方括号内

边界情况

：

| 场景      | 行为                                                |
| ------- | ------------------------------------------------- |
| 空链接文本   | `[](url)` → 渲染为链接（但视觉上可能只有下划线无文字）                 |
| URL 含括号 | `[text](<url(with)parens>)` → 用尖括号包裹 URL          |
| 自动链接    | `<https://example.com>` → 自动渲染为可点击链接              |
| 裸 URL   | `https://example.com` → 自动检测并渲染为链接（首期可选，Typora 有） |
| 邮件链接    | `<user@example.com>` → 渲染为 `mailto:` 链接           |
| 引用式链接   | `[text][ref]` / `[ref]: url` →   首期不支持  ，后续按需加入   |
| 链接内嵌套格式 | `[**bold link**](url)` → 渲染时链接内的加粗正常显示            |

实现要点

：Milkdown 的 `link` mark。需要映射 `Ctrl+K` 快捷操作。引用式链接需要 parser 支持但首期可忽略。

***

### 2.7 图片 `![alt](url)`

渲染态

：

* 直接显示图片，`![alt]` 部分不可见

* 图片宽度不超过编辑器内容区宽度，超出时等比缩放

* 点击图片：弹出灯箱全屏查看

* 图片加载失败：显示破损图标 + alt 文字 + "图片加载失败"提示

编辑态

：

* 光标在图片节点内时：显示 `![alt](url)` 语法标记（Typora 的做法是弹出小编辑框）

* 首期做简化版：点击图片显示一个小工具栏（替换图片、复制、删除），语法标记不单独显示

图片灯箱

：

```
┌──────────────────────────────────────────┐
│                                    [✕]   │  ← 关闭按钮
│                                          │
│              [  图片全屏  ]              │
│                                          │
│  文件名.png                    1.2 MB    │  ← 底部信息栏
└──────────────────────────────────────────┘
```

* 点击遮罩区或按 Esc 关闭

* 支持鼠标滚轮缩放

* 大图可拖拽平移

边界情况

：

| 场景                | 行为                                               |
| ----------------- | ------------------------------------------------ |
| 图片路径不存在           | 显示破损图标 + alt 文字                                  |
| 图片在 `images/` 子目录 | 相对路径 `./images/pic.png` 或 `images/pic.png` 都正确解析 |
| 网络图片 URL          | `![](https://...)` → 也直接渲染（首期不做网络请求限制）           |
| 超大图片              | 限制最大渲染宽度为编辑器内容宽度，高度按比例                           |
| SVG 图片            | 直接渲染（SVG 本身是矢量），但禁止执行内嵌脚本（安全）                    |
| GIF 图片            | 直接渲染并播放动画（不做限制）                                  |

## 3. 块级元素

### 3.1 标题 `# H1` ~ `###### H6`

渲染态

：

* 按对应字号+字重渲染（H1: 28px/700, H2: 22px/600, H3: 18px/600, H4: 16px/600, H5: 15px/500, H6: 14px/500）

* `#` 符号不可见

* 标题下方有适当的 `margin-bottom`（H1: 24px, H2: 16px, H3: 12px, H4-H6: 8px）

编辑态

：

* 光标进入标题行时，行首 `#` 以语法标记色显示

* 标题文字保持放大+加粗的样式不变

* 闭合式标题 `### Title ###` 的尾部 `###` 也以语法标记色显示

快捷键

：

* `Ctrl+1` ~ `Ctrl+6`：设置当前行为对应级别标题

* `Ctrl+0`：取消标题，变回普通段落

* 光标在行首时按退格键：如果前面有 `#`，退格删掉最后一个 `#`（降级），全删完后变普通段落

边界情况

：

| 场景           | 行为                                                        |
| ------------ | --------------------------------------------------------- |
| `#` 后有空格才生效  | `#Heading` → 普通文字。`# Heading` → H1                        |
| 行首空格后的 `#`   | `  # Heading` → 在 CommonMark 中允许最多 3 个空格缩进。首期严格模式：行首不能有空格 |
| `#` 在段落中间    | `text # not heading` → 普通文字，不触发标题                         |
| 标题内嵌套格式      | `# **Bold Title**` → 正常渲染粗体标题                             |
| 超过 6 级       | `####### text` → 渲染为普通段落（`#` 后无空格则不触发）                    |
| 标题后紧跟内容（同一行） | `# Title some text` → 整行都是 H1 标题内容，包括 `some text`         |

### 3.2 引用块 `> quote`

渲染态

：

* 左侧 3px 竖线（亮色 `#E5E5E5`，暗色 `#3E3E3E`）

* 文字颜色略淡于正文（可选，Typora 不改变文字颜色，仅靠竖线区分）

* 背景可以有极浅的灰色（首期建议不加背景，保持简洁）

编辑态

：

* 行首 `>` 以语法标记色显示

* 嵌套引用 `>> nested`：显示两个 `>`，竖线也分两级

快捷键

：`Ctrl+Shift+.`（或直接输入 `>␣`）

边界情况

：

| 场景        | 行为                                                  |
| --------- | --------------------------------------------------- |
| `>` 后无空格  | `>quote` → 在 CommonMark 中允许。首期统一要求空格，否则不渲染          |
| 空引用行      | `>` 后面什么都没 → 渲染为空引用行（有竖线无内容）                        |
| 引用块内的其他元素 | `> - list item` → 引用内可以包含列表。`> `code\` → 引用内可以包含代码块 |
| 引用块结束     | 连续两个回车退出引用块。单回车继续下一行引用                              |
| 懒继续       | Typora 对单回车的下一行自动加 `>`。首期不做懒继续，用户需手动输入              |

***

### 3.3 无序列表 `- ` / `* ` / `+ `

渲染态

：

* 圆点符号以正常文字色显示（不是浅色）

* 缩进由编辑器控制（与正文左边距对齐）

* 列表项之间间距略小于段落间距

编辑态

：

* 光标在列表项内时，行首的 `-` 标记以语法标记色显示

自动行为

：

* 在列表项末尾按 `Enter`：自动创建新的列表项（同层级）

* 连续按两次 `Enter` 或在新空列表项上按 `Backspace`：退出列表

* `Tab` 在行首：增加缩进（子列表），符号自动切换（`-` → 下一层仍用 `-`）

* `Shift+Tab` 在行首：减少缩进

* 有序列表中 `Enter` 后自动递增序号

边界情况

：

| 场景      | 行为                                 |
| ------- | ---------------------------------- |
| 三种符号混用  | `-`、`*`、`+` 都可以，同一列表内混用会导致分割       |
| 列表项内多段落 | 用缩进（4空格或Tab）续写新段落                  |
| 空列表项    | `- ` → 有效，渲染为一个空 bullet            |
| 列表嵌套代码块 | ` ```code``` → 需要在` \`\`\` \` 前加缩进 |

***

### 3.4 有序列表 `1. ` / `1) `

与无序列表共享上述所有自动行为

，额外规则：

自动编号

：

* 用户永远不需要手动维护序号

* WYSIWYG 模式下，源码中每个条目都可以写 `1.`，渲染时自动递增

* 用户在渲染态看到的序号由编辑器计算得出

* 用户在编辑态看到的是源码中的实际数字

* 插入/删除条目时自动重排后续序号

起始序号

：

* 有序列表的起始序号由第一个条目的数字决定

* `3. item` → 渲染从 3 开始

边界情况

：

| 场景      | 行为                               |
| ------- | -------------------------------- |
| 非 1 起始  | `3. first` → 渲染为从 3 开始，后续自动递增    |
| `1)` 格式 | 也支持，但右键括号的渲染保持为 `1.` 风格          |
| 列表中断    | 中间插入非列表段落会中断列表，后续条目变为新列表（从 1 开始） |

***

### 3.5 任务列表 `- [ ] ` / `- [x] `

渲染态

：

* 显示可交互的复选框：

  * 未完成 `- [ ]`：空心方框 `☐`

  * 已完成 `- [x]`：实心方框 `☑`（带勾），文字颜色变淡 + 删除线

* 点击复选框直接切换完成状态

编辑态

：

* 行首的 `- [ ]` 以语法标记色显示（或仅 `-` 和 `[ ]` 标记可见）

* 点击复选框时同步修改底层 Markdown 源码：`[ ]` ↔ `[x]`

为什么点击要修改源码

：这是 Typora 的核心体验——所见即所得意味着操作 UI 等价于编辑源码。用户切换到源码模式后看到的也是 `- [x]`。

边界情况

：

| 场景             | 行为                                  |
| -------------- | ----------------------------------- |
| `[x]` 中 x 的大小写 | `[x]` 和 `[X]` 都视为已完成，统一规范化为小写 `[x]` |
| 中间状态           | 不存在。任务只有完成/未完成两态                    |
| 任务列表嵌套         | 父任务的完成状态不影响子任务                      |

***

### 3.6 分割线 `---` / `***` / `___`

渲染态

：一条水平分割线（`<hr>`），颜色使用边框色（`#E5E5E5` 或 `#3E3E3E`），宽度 100%。

编辑态

：光标移动到该行时，显示原始字符。但由于 `<hr>` 是不可编辑节点，在 ProseMirror 中它可能作为一个 block node 存在。

边界情况

：

| 场景            | 行为                                                        |
| ------------- | --------------------------------------------------------- |
| `---` 紧跟前一行文字 | 必须是独立行。前一行文字后直接跟 `---` 会被视为 YAML front matter 或 setext 标题 |
| 多于 3 个        | `------` → 仍然渲染为 hr                                       |
| `- - -` (带空格) | 不渲染为 hr，是普通文字                                             |
| `***` 在列表中    | 列表项内的 `***` 不渲染为 hr                                       |

***

### 3.7 围栏代码块

渲染态

：

* 深色背景（亮色 `#F6F8FA`，暗色 `#1E1E1E`）+ 等宽字体

* 顶部显示语言标签（从 ` ```language` 提取），右上角复制按钮

* 语法高亮着色

* 行号可选（默认关，首期不做）

* 横向滚动（代码行过长时）

编辑态

：

* 光标在代码块内时：代码块保持语法高亮，边框略微变化表示聚焦

* 上下的 ` ``` ` 围栏始终可见（这是块的边界）

* 点击代码块外部空白区域 → 光标可能难以定位。建议：代码块上下左右各留 8px 不可点击缓冲区（由 Milkdown 自带）

语言标签

：

* 输入 ` ```javascript ` → 顶部显示 "JavaScript"

* 不输入语言 → 显示 "text" 或不显示标签

* 输入未知语言 → 显示原始语言名，不高亮但代码块样式保留

复制按钮交互

：

* 点击后按钮从「复制」图标变为「✓ 已复制」

* 1.5 秒后恢复为「复制」图标

* 复制的文本不包含 ` ``` ` 围栏，纯代码内容

边界情况

：

| 场景            | 行为                                        |
| ------------- | ----------------------------------------- |
| 代码块嵌套         | Markdown 不支持。` ``` ` 遇到下一个 ` ``` ` 即认为闭合  |
| 代码块内的 ` ``` ` | 用更多反引号：` ```` ```` `。极少见场景，首期不支持          |

## 5. 自动补全与配对

### 5.1 符号自动配对

当用户输入以下字符时，自动补全右侧配对符号，并将光标置于中间：

| 输入         | 补全结果   | 光标位置    | <br />               |
| ---------- | ------ | ------- | -------------------- |
| `*`        | `**`   | \`\*    | \*\`                 |
| `**`（连续两个） | `****` | \`\*\*  | \*\*\`（用于加粗）         |
| `(`        | `()`   | \`(     | )\`                  |
| `[`        | `[]`   | \`\[    | ]\`                  |
| `{`        | `{}`   | \`{     | }\`                  |
| `` ` ``    | ` `` ` | \`\` \` | \` \`\`              |
| `$`        | `$$`   | \`\$    | $\`（预留数学公式）          |
| `~`        | `~~`   | \`\~    | \~\`（用于删除线，在文字输入场景下） |
| `"`        | `""`   | \`"     | "\`                  |
| `'`        | `''`   | \`'     | '\`                  |

智能行为

：

* 右侧已有同一字符且光标紧挨时：不补全，跳过（光标右移一位）

* 选中文字后输入配对符号：用配对符号包裹已选文字（如选中 `text` 输入 `(` 得到 `(text)`）

* 退格删除左符号时：同时删除右符号（仅在配对符号内容为空时）

### 5.2 Markdown 结构自动补全

| 输入                 | 补全                | 说明        | <br />                |
| ------------------ | ----------------- | --------- | --------------------- |
| ` ``` ` + Enter    | 自动闭合 ` ``` ` + 空行 | 光标置于中间行   | <br />                |
| ` ```lang` + Enter | 同上                | 语言标签保留在首行 | <br />                |
| 输入 \`              | \`                | 触发表格模式建议  | 如果检测到前一行有表格结构，建议继续表格行 |

### 5.3 列表自动继续

* 在列表项末尾按 `Enter`：自动插入同类型列表标记

* 对于有序列表：序号自动 +1

* 对于空列表项按 `Enter` 或 `Backspace`：退出列表

### 5.4 链接快捷输入

选中文字后：

* `Ctrl+K`：包裹为 `[文字](url)`，光标跳到 `url` 位置

* 粘贴 URL（ctrl+v）在选中文字上：自动转换为 `[文字](url)`

## 7. 撤销/重做粒度

ProseMirror（Milkdown 底层）的 `history` 插件已提供合理的撤销粒度。需要额外注意：

* 每个字符输入是单独的撤销步（`newGroupDelay` 默认 500ms，即 500ms 内的连续输入归为一组）

* 自动补全操作（如输入 `**` 自动补上闭合的 `**`）应作为一个原子操作归入同一撤销组

* 列表自动继续（`Enter` 后自动插入 `-`）应与 `Enter` 键合并在一个撤销组

自定义 meta

：通过 ProseMirror 的 `tr.setMeta('addToHistory', false)` 可以让某些自动操作不产生独立的撤销记录。

## 8. 特殊字符与转义

反斜杠转义

：`\*text\*` → 渲染为 `*text*` 字面字符，不是斜体。

支持转义的字符

：

```
\   backslash
`   backtick
*   asterisk
_   underscore
{}  curly braces
[]  square brackets
()  parentheses
#   hash
+   plus
-   minus
.   dot
!   exclamation
|   pipe
~   tilde
```

渲染态

：转义后的字符正常显示，前导 `\` 不可见。

编辑态

：`\` 和转义字符都可见，`\` 以语法标记色显示。

HTML 实体

：如 `&amp;` `&lt;` `&gt;` → 在渲染时转换为对应字符，编辑时显示实体原文。
