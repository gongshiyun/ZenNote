# ZenNote 应用交互体验评审&完善方案

> 评审视角：Apple Human Interface Guidelines 水准的全链路体验审计。
> 范围：编辑器以外的所有用户触点——从双击桌面图标到关闭窗口的完整旅程。

***

## 一、评审总览

对三份已有文档（PRD、UI-DESIGN、MARKDOWN-RENDERING）进行全链路体验扫描，发现   8 大类、32 项缺失或缺陷  。按影响等级分布：

| 等级    | 数量   | 说明              |
| ----- | ---- | --------------- |
| 🔴 P0 | 6 项  | 缺失则产品不可用或严重断裂   |
| 🟠 P1 | 11 项 | 显著影响日常使用体验      |

## 二、P0 级问题（影响基础可用性）

### P0-1 自定义标题栏完全缺失

现状

：文档里连"标题栏"三个字都没出现。UI-DESIGN 的布局图中从工具栏往上就直接到屏幕顶了——但 Windows 窗口是有标题栏的。

问题

：Tauri 默认使用系统原生标题栏。Windows 11 的原生标题栏是白色/深灰 + 圆角，高度约 32-48px（含窗口控制按钮）。如果什么都不做，ZenNote 的界面会变成：

```
┌────────────────── Windows 原生标题栏（白底黑字）─────────── [─][□][✕] ─┐
├────────────────── 工具栏 36px  ──────────────────────────────────────────┤
├──── 文件树 ────┬──────── 编辑器 ────────────┬──────── 大纲 ──────────────┤
```

原生标题栏与极简的 36px 工具栏之间会形成一条生硬的视觉断层：两套不同的背景色、不同的字体、不同的设计语言叠在一起。

方案

：使用 Tauri 的无边框窗口 + 自定义标题栏。

```
┌──── 自定义标题栏区（与工具栏融合，共 36px）────────── [─][□][✕] ─┐
│ ☰  ≡  文件名.md                                ⏷  ⋮              │
├──── 文件树 ────┬──────── 编辑器 ────────────┬──────── 大纲 ───────┤
```

实现要点：

* Tauri `tauri.conf.json` 中设置 `"decorations": false`

* 自定义标题栏承载：拖拽移动窗口、窗口控制按钮、当前文件名

* 窗口控制按钮（最小化/最大化/关闭）使用与主题匹配的自定义图标

* 标题栏区域支持双击最大化/还原（Windows 标准行为）

* 窗口控制按钮 hover 时背景变化，关闭按钮 hover 时变红色（`#E81123`）

标题栏规格：

| 元素     | 位置            | 说明                     |
| ------ | ------------- | ---------------------- |
| 应用图标   | 左上角 8px 处     | 16px 图标，无文字            |
| 拖拽区域   | 图标右侧到窗口控制按钮左侧 | 按住任意空白处可拖拽窗口           |
| 窗口控制按钮 | 右上角           | 三个按钮（─ □ ✕），每个 46×32px |

颜色

：

* 亮色：背景同编辑器 `#FFFFFF`，按钮 hover `#F0F0F0`，关闭按钮 hover `#E81123`（文字变白）

* 暗色：背景同编辑器 `#1E1E1E`，按钮 hover `#3A3A3A`，关闭按钮 hover `#E81123`

### P0-2 面板尺寸不可拖拽调整

现状

：文件树固定 240px，大纲固定 200px。不可拖拽。

问题

：用户文件夹名长短不一、标题层级深浅不同，固定宽度要么浪费空间要么截断内容。这是基础可用性问题。

方案

：面板间可拖拽分隔条。

```
文件树 ──┬── 编辑器 ──┬── 大纲
    ↑ 拖拽手柄    ↑ 拖拽手柄
```

* 拖拽手柄宽度 4px，hover 时变为 6px + 显示高亮色（`#3B82F6`），光标变为 `col-resize`

* 文件树最小宽度 160px，最大 480px

* 大纲最小宽度 140px，最大 360px

* 编辑器最小宽度 360px（保证内容区不低于 300px）

* 拖拽时显示半透明引导线，松手后即时生效

* 用户调整后的宽度保存到应用配置中

边界

：当窗口宽度不足以容纳所有面板的最小宽度时，优先压缩大纲（到 140px），再压缩文件树（到 160px），最后保护编辑器（最小 360px）。

### P0-4 文件操作缺少内联编辑与撤销保护

现状

：PRD 提了右键菜单有"新建/重命名/删除"，但没有交互细节。

问题清单

：

新建文件

：

* 现状未定义。最佳实践：点击「＋」→ 文件树末尾出现一个内联输入框，预填"未命名.md"，光标选中文件名部分（不含扩展名），用户直接输入名字后按 Enter 确认。Esc 取消并删除占位文件。

* 新建后自动打开该文件，光标定位到编辑器第一行。

* 如果用户新建在深层目录，文件树应自动展开路径并滚动到新文件。

重命名（内联编辑）

：

* 不是弹对话框。右键 → "重命名" → 文件名变为可编辑的 input，光标选中文件名主体（不含扩展名）。

* Enter 确认，Esc 取消。

* 文件名不能包含 `\ / : * ? " < > |`，输入时实时校验，非法字符阻止输入或变红提示。

* 重名冲突：如果目标名称已存在，拒绝并提示"该位置已存在同名文件"（状态栏显示 3 秒）。

删除确认

：

* 删除当前未打开的笔记 → 直接删除（移入回收站），状态栏提示"已移至回收站"，提供"撤销"链接（3 秒内可点击恢复）。

* 删除当前正在编辑的笔记 →   不可以  。应弹出 "「xxx.md」正在编辑中，无法删除"。

### P0-5 切换文件时无状态保护

现状

：没有任何关于切换文件的描述。默认理解是"点另一个文件，编辑器内容替换"。

问题

：

1. 切换时当前文件的撤销历史怎么办？
2. 如果 auto-save 的 debounce 还没触发（编辑后立即切换）→ 内容丢失。
3. 切换后回来，滚动位置是否保留？

方案

：

切换流程

：

```
用户点击文件 B
  │
  ├─ 当前文件 A 有未保存修改？
  │   ├─ 是 → 立即触发一次保存（不等 debounce）
  │   └─ 否 → 跳过
  │
  ├─ 在内存中缓存文件 A 的状态：
  │   ├─ 当前内容
  │   ├─ 滚动位置（scrollTop）
  │   ├─ 光标位置
  │   └─ 撤销历史（如果要跨文件保留）
  │
  ├─ 编辑器显示加载过渡（200ms）：内容区轻微淡出 → 新内容淡入
  │
  ├─ 加载文件 B 内容 → 渲染
  │
  └─ 光标定位到文件顶端
```

滚动位置记忆

：

* 每个已打开过的文件记住其最后滚动位置

* 切换回来时恢复到该位置

* 应用重启后不保留（简单策略，避免配置膨胀）

未保存内容保护

：

* 文件名旁的圆点标记表示 isDirty

* 如果文件已被外部程序修改（如在 VS Code 中也打开了同一个文件）：切换回来时检测到文件修改时间戳变化 → 提示"文件已被外部修改"→ 用户选择"重新加载"或"保留当前内容"。

### P0-6 大量错误场景未定义恢复路径

现状

：只说了"保存失败时状态栏提示 3 秒"。任何复杂点的错误都没有处理。

需要补充的错误场景

：

| 场景                    | 严重程度 | 恢复方案                                            |
| --------------------- | ---- | ----------------------------------------------- |
| 打开工作区时文件夹不存在（已被删除/移动） | 阻断   | 提示"文件夹不存在，可能已被移动或删除"，从最近列表移除，引导选择新工作区           |
| 工作区无读取权限              | 阻断   | 提示"无权限访问该文件夹"，引导选择其他文件夹                         |
| 打开文件时文件不存在（已被外部删除）    | 阻断   | 文件树刷新 → 该文件消失。如果该文件正被编辑，切换到空状态，状态栏提示            |
| 保存时磁盘空间不足             | 严重   | 状态栏变红提示"磁盘空间不足，请清理后重试"。保持 isDirty 状态。。。不做沉默丢失。。 |
| 保存时文件被其他程序锁定          | 严重   | 状态栏变红提示"文件被其他程序占用"。3 秒后自动重试一次                   |
| 导出 HTML/PDF 失败        | 中等   | 模态提示具体错误原因，提供重试按钮                               |
| 粘贴的图片超过 10MB          | 中等   | 弹出确认对话框 "图片 XX MB，确定插入？"                        |
| 粘贴的图片格式不支持            | 低    | 状态栏提示"不支持的图片格式"（HEIC、TIFF 等非 Web 格式）            |
| Mermaid 渲染超时          | 低    | 代码块内显示灰色提示"图表渲染超时，点击重试"                         |
| 文件编码不是 UTF-8          | 中等   | 尝试读取，乱码时提示"文件编码非 UTF-8，可能无法正确显示"                |

## 三、P1 级问题（显著影响日常体验）

### P1-1 缺少全局搜索

问题

：一个笔记软件没有跨文件搜索，用户找笔记只能靠记忆+肉眼扫描文件树。文件夹超过 30 个笔记后这就是灾难。

方案

：

* `Ctrl+Shift+F` 打开全局搜索

* 搜索栏在编辑器上方展开（不是模态框）

* 实时过滤（输入即搜，debounce 200ms）

* 搜索结果列表：文件名 + 匹配行预览 + 高亮关键词

* 点击结果 → 打开文件并跳转到匹配行

* 搜索范围：当前工作区下所有 `.md` 文件

```
┌─────────────────────────────────────────────┐
│ 🔍 [____________]  共 12 个结果    [✕]      │
├─────────────────────────────────────────────┤
│ 📄 项目规划.md                              │
│    第 15 行: ...讨论**技术选型**方案...     │
│ 📄 会议记录.md                              │
```

### P1-3 文件树键盘导航缺失

问题

：纯鼠标操作的文件树效率极低。没有键盘支持 = 不专业。

方案

：

| 按键             | 行为                   |
| -------------- | -------------------- |

### P1-4 外部文件变更检测不完整

问题

：ZenNote 是一个本地文件编辑器，笔记文件夹里的文件可能被其他程序（VS Code、记事本、Git pull 等）修改。目前完全没有提到这个场景。

方案

：

检测机制

：Tauri 的 Rust 侧可以用 `notify` crate 监听工作区目录的文件系统事件。

检测到外部修改时

：

| 文件状态          | 行为                                        |
| ------------- | ----------------------------------------- |
| 未打开的文件被外部修改   | 静默刷新文件树（时间戳/文件大小），不做任何提示                  |
| 当前编辑的文件被外部修改  | 编辑器顶部显示黄色提示条："文件已被外部修改。\[重新加载] \[保留我的版本]" |
| 当前编辑的文件被外部删除  | 编辑器显示灰色提示 "文件已被删除"，内容保留在编辑器中（用户仍可另存）      |
| 有新文件被添加到工作区   | 文件树自动刷新，新文件出现在对应位置，无提示                    |
| 当前编辑的文件被外部重命名 | 更新 `currentFilePath`，文件名在标题栏自动更新          |

### P1-5 面板折叠/展开的焦点处理缺失

问题

：折叠文件树后，焦点去了哪里？折叠大纲后，再次展开时光标还在编辑器里吗？

方案

：

* 折叠面板：焦点自动移到编辑器。如果编辑器无焦点（不太可能），焦点到文件树的下一个可聚焦元素。

* 展开面板：焦点不移动（用户大概率在编辑器中，不想被打断）。

* 快捷键 `Ctrl+B` 折叠→展开是一个来回：展开后焦点回到面板内。

### P1-6 加载状态缺少视觉反馈

问题

：打开大工作区（几百个文件）、打开大笔记（1 万行）时，界面会"卡住"。用户不知道是在加载还是崩溃了。

方案

：

文件树加载

：

* <br />

  > 100ms：文件树区域显示骨架屏（3-5 个灰色闪烁条，模拟树节点外观）

* <br />

  > 2s：骨架屏 + 右上角显示"加载中..."

* 加载完成后骨架屏溶解淡出（300ms）

大文件打开

：

* <br />

  > 200ms：编辑器区域显示骨架屏（模拟 3 个段落 + 标题）

* 加载完成后内容淡入（200ms）

图片粘贴处理

：

* 粘贴大图（> 5MB）时：光标位置出现一个灰色占位框 "正在处理图片..."，处理完成后替换为图片。

### P1-10 滚动行为未细化

问题

：文档没提滚动。但 Typora 的平滑滚动和滚动位置记忆是体验关键。

方案

：

* 编辑器使用用用平滑滚动用用（`scroll-behavior: smooth`）——仅对编程跳转（大纲点击、查找跳转），用户手动滚动不做干预

* 大纲点击跳转：平滑滚动到目标标题，偏移 -40px（考虑工具栏高度遮挡）

* 大纲和编辑器滚动联动已经定了（节流 100ms），需补充：当用户手动滚动大纲区域时，编辑器跟随滚动

问题

```
                              │                              │
```

第二次及以后启动

## 四、P2 级问题（精致度打磨）

### P2-1 文件树节点 hover 态缺少过渡

现状

：提到了 hover 颜色，但没说过渡时间。

方案

：所有 hover 状态使用 `transition: background-color 150ms ease`。无过渡的 hover 会显得"硬"，有过渡则质感提升一档。

### P2-2 侧边栏折叠动画缺少缓动函数

现状

：说了 200ms，没说缓动。

方案

：侧边栏折叠用 `cubic-bezier(0.4, 0, 0.2, 1)`（Material Design 标准缓出），关闭时感觉"干脆"，展开时感觉"平滑"。

### P2-3 查找替换无匹配计数和无结果态

方案

：

* 查找栏右侧显示 "3/15"（当前匹配/总匹配）

* 无匹配时输入框变红 1 秒 + 显示"无结果"

* 到达最后一个匹配后继续点"下一个"→ 循环回第一个，并显示"已到达末尾，从开头继续"

### P2-4 状态栏信息过于静态

问题

：状态栏目前像是静态文本，缺少"活"的感觉。

改进

：

* 光标位置变化时数字平滑过渡（用 `requestAnimationFrame`）

* 字数达到整千时做一个微小的跳动动画（无伤大雅的小趣味）

* 文件保存成功后 isDirty 圆点消失时做一个极短的淡出（150ms）

### P2-5 大纲面板中的标题过长截断没有省略号规范

方案

：

* 标题超过面板宽度时：`text-overflow: ellipsis` + `white-space: nowrap`

* Hover 时 tooltip 展示完整标题（延迟 500ms 出现，避免频繁弹）

### P2-6 代码块复制按钮反馈不完整

方案

：

* 点击复制 → 按钮图标变为 ✓ + 文字 "已复制"（不是只换图标）

* 1.5 秒后自动恢复为复制图标

* 复制失败时（虽然极少见）→ 按钮闪烁红色 "复制失败"

### P2-7 暗色模式切换时页面闪白

问题

：如果先切换 CSS 类再重新渲染 Mermaid，中间有一个短暂的白屏闪烁。

方案

：

1. 在 `<html>` 上设置 `transition: background-color 200ms ease, color 200ms ease`
2. Mermaid 图表在主题切换时：先隐藏 → 重渲染 → 再显示（用 opacity 过渡避免闪白）

### P2-8 导出时缺少进度反馈

方案

：

* PDF 导出可能较慢（尤其是含大量 Mermaid 图表的文档）

* 点击导出后：按钮变为 "正在导出..." + 旋转动画

* 超时 30 秒后：提示"导出超时，请重试"

* 成功时：按钮变为 "导出成功 ✓"（1 秒），然后对话框关闭，打开文件夹

### P2-9 无拖放文件到窗口的交互反馈

方案

：

* 拖放 `.md` 文件或文件夹到 ZenNote 窗口时：

  * 鼠标进入窗口 → 整个窗口蒙上一层半透明蓝色 `rgba(59, 130, 246, 0.1)` + 边框变蓝

  * 表示"可以放在这里"

  * 松手后：如果是文件夹 → 切换工作区；如果是 `.md` 文件 → 在该文件所在目录打开并选中该文件

### P2-10 滚动条样式未设计

方案

：

* 使用自定义细滚动条（Webkit `::-webkit-scrollbar`）

* 宽度 6px，常态透明，hover 时显示半透明灰色（亮色 `#D0D0D0`，暗色 `#4A4A4A`）

* 这样滚动条"存在但不可见"，符合极简理念

## 六、交互细节补充汇总

这些是不值得单独开一条、但开发时不能丢的细节：

1. Esc 键的全局行为  ：关闭最顶层的浮层/对话框/菜单；如果都没有 → 不做任何事（不退出程序）
2. Ctrl+W 关闭当前笔记  ：不是关闭应用，是"关闭当前文件"（回到空状态或打开上一个文件）
3. 文件扩展名显示  ：文件树中文件名默认显示完整（含 `.md`），设置中可关闭
4. 链接点击行为  ：`Ctrl+Click` 在浏览器打开（防止误触），普通 Click 触发链接编辑态
5. 窗口位置记忆  ：存储位置、尺寸、是否最大化。如果上次是在第二块屏幕上关闭的而现在那块屏幕已拔掉 → 回到主屏幕居中显示
6. 文本选择拖拽  ：选择文字后可以拖拽到编辑器其他位置（移动文字），按住 Ctrl 拖拽是复制
7. 三击选中段落  ：在编辑器内三击鼠标选中当前段落
8. 双击选中词  ：按词边界选中（中文按标点/空格分词）
9. Ctrl+Home/End  ：跳转到文档开头/结尾
10. Ctrl+↑/↓  ：以段落为单位上下滚动（不移动光标）
