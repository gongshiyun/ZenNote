## 核心组件
- 导出库（exportNote.ts）
  - 职责：封装导出为 Markdown/PDF/图片等格式的前端逻辑，协调浏览器原生能力或调用 Tauri 命令完成本地写入。
  - 关键能力：生成文件内容、选择保存路径（通过 Tauri）、触发下载或落盘、错误提示与进度反馈。
- 应用层（App.tsx）
  - 职责：提供导出按钮与菜单项，收集当前笔记内容与元数据，调用导出库并展示结果。
- Tauri 后端（lib.rs / main.rs）
  - 职责：暴露系统级文件写入能力，处理跨平台路径解析与权限问题，返回成功/失败状态。

## 架构总览
导出功能的整体交互流程如下：
- 用户在界面触发“导出”
- 前端根据目标格式组装内容（Markdown/HTML/图片资源）
- 若需落盘，则通过 Tauri 命令调用系统文件系统写入
- 成功后返回结果，前端更新 UI 提示

```mermaid
sequenceDiagram
participant U as "用户"
participant A as "应用(App.tsx)"
participant E as "导出库(exportNote.ts)"
participant B as "浏览器API"
participant T as "Tauri命令(lib.rs)"
participant F as "文件系统"
U->>A : 点击“导出”
A->>E : 传入笔记内容与格式参数
alt 浏览器直接下载
E->>B : 创建 Blob/URL 并触发下载
B-->>E : 下载完成
E-->>A : 返回成功
else 调用 Tauri 落盘
E->>T : 调用写文件命令(路径, 内容, 格式)
T->>F : 写入文件
F-->>T : 成功/失败
T-->>E : 返回结果
E-->>A : 返回成功/失败
end
A-->>U : 显示导出结果
```

## 详细组件分析

### 导出库（exportNote.ts）
- 设计要点
  - 统一导出接口：按格式分发处理（Markdown、PDF、图片等）
  - 资源处理：内联图片、相对路径转换、样式注入（如 PDF）
  - 交互反馈：加载态、错误捕获、用户提示
- 复杂度与优化
  - 大文档分块处理，避免主线程阻塞
  - 使用流式写入（通过 Tauri）降低内存峰值
  - 缓存已生成的中间产物，减少重复计算

```mermaid
flowchart TD
Start(["开始"]) --> PickFormat["选择导出格式"]
PickFormat --> |Markdown| BuildMD["构建 Markdown 内容"]
PickFormat --> |PDF| BuildHTML["渲染 HTML + 样式"]
PickFormat --> |图片| RenderImg["渲染图片资源"]
BuildMD --> SavePath{"是否直接下载?"}
BuildHTML --> SavePath
RenderImg --> SavePath
SavePath --> |是| BrowserDL["浏览器下载(Blob/URL)"]
SavePath --> |否| TauriWrite["调用 Tauri 写文件"]
BrowserDL --> Done(["完成"])
TauriWrite --> Result{"写入成功?"}
Result --> |是| Done
Result --> |否| HandleErr["错误处理与提示"]
HandleErr --> End(["结束"])
```

## 性能考虑
- 大文档导出
  - 使用流式写入（Tauri）避免一次性加载全部内容
  - 对图片等资源进行压缩或懒加载
- 渲染开销
  - 将重渲染任务放入 Web Worker（如需要）
  - 控制 DOM 规模，避免复杂样式导致的布局抖动
- 内存管理
  - 及时释放临时 URL 与对象引用
  - 分批处理长列表或表格

## 故障排查指南
- 常见错误
  - 路径无效或无写入权限：检查 Tauri 命令返回码与系统权限
  - 资源缺失导致导出异常：确认图片与样式是否内联或可访问
  - 浏览器下载被拦截：检查弹窗策略与安全设置
- 定位步骤
  - 查看控制台日志与网络面板
  - 启用 Tauri 调试输出，观察命令执行链路
  - 复现最小用例，逐步缩小范围
